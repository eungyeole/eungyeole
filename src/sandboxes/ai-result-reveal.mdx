요즘 제품에 AI 기능을 반영하는 일이 많아졌습니다. 익숙한 화면 안에서도 이 기능이 AI가 만든 결과라는 인상을 전달할 장치가 필요해졌습니다.

AI 결과는 계산을 기다린 뒤 도착합니다. 결과가 화면에 바로 붙으면 완료된 순간이 잘 느껴지지 않고, 움직임을 계속 반복하면 내용을 읽는 데 방해가 됩니다. 그래서 짧은 빛이 카드를 한 바퀴 돈 뒤 테두리로 남는 효과를 만들었습니다. 등장할 때만 AI다운 인상을 주고, 이후에는 평범한 결과 카드로 돌아옵니다.

## border로는 움직이는 그라디언트를 다루기 어렵다

CSS의 `border`는 네 면의 두께와 색, 선 모양을 표현하는 데 적합합니다. 하지만 `border-color`에는 그라데이션을 넣을 수 없습니다. `border-image`를 사용하면 그라데이션 이미지를 테두리에 배치할 수 있지만, 둥근 모서리를 따라 하나의 빛을 회전시키거나 선에만 블러를 적용하기는 어렵습니다.

필요한 것은 네 개의 선이 아니라 카드 뒤에서 회전하는 하나의 평면이었습니다. 그래서 테두리를 직접 그리지 않고 `conic-gradient` 배경을 만들었습니다. 아래는 아직 카드를 올리지 않은 배경 레이어입니다. 오른쪽 위 버튼으로 멈춰보면 색이 있는 짧은 구간과 나머지 투명한 영역을 확인할 수 있습니다.

이 큰 배경 하나만 회전합니다. 실제 카드에서는 중앙을 불투명한 요소로 덮어 가장자리의 일부만 보이게 만듭니다.

## 배경을 테두리처럼 보이게 만든다

그라데이션 배경을 카드 뒤에 깔고, 그 위에 불투명한 카드를 올립니다. 부모의 얇은 `padding` 사이로 뒤의 배경이 드러나면서 하나의 테두리처럼 보입니다.

```css
.frame {
  position: relative;
  isolation: isolate;
  contain: paint;
  padding: 2px;
  border-radius: 18px;
}

.frame::before {
  content: "";
  position: absolute;
  z-index: 0;
  left: 50%;
  top: 50%;
  width: 200%;
  height: 200%;
}

.card {
  position: relative;
  z-index: 1;
  border-radius: 16px;
  background: var(--surface);
}
```

배경과 카드를 별도 레이어로 나누면 내용은 가만히 둔 채 뒤의 배경에만 애니메이션을 적용할 수 있습니다. 블러도 배경 레이어에만 적용되므로 글자와 아이콘은 선명하게 남습니다.

배경은 카드보다 크게 만들었습니다. 사각형을 같은 크기로 회전시키면 모서리를 덮지 못하는 순간이 생기기 때문입니다. `contain: paint`는 커진 배경을 바깥쪽 라운드 안에서 잘라냅니다. 안쪽 카드는 그보다 작은 반경으로 덮어 두 레이어의 곡선도 자연스럽게 맞췄습니다.

## 원뿔 그라데이션으로 짧은 빛을 만든다

배경에는 `conic-gradient`를 사용했습니다. 원의 중심을 기준으로 색의 시작과 끝을 각도로 정할 수 있어, 테두리를 따라 움직이는 짧은 빛을 만들기 좋습니다.

```css
background: conic-gradient(
  var(--lead) 0deg 60deg,
  var(--trail) 60deg var(--fill-angle),
  transparent var(--fill-angle) 360deg
);
```

처음 `--fill-angle`은 `90deg`입니다. 원의 일부만 색을 가지고 나머지는 투명하므로 짧은 호만 보입니다. 이 배경 레이어 전체를 중심축으로 회전시키면 호가 카드의 네 면을 끊김 없이 지나갑니다.

## 회전하던 빛을 테두리로 남긴다

한 바퀴가 끝난 뒤 별도의 테두리로 교체하면 두 장면이 끊겨 보입니다. 같은 그라데이션에서 색이 차지하는 범위만 넓히면 회전하던 빛을 그대로 완료 상태로 연결할 수 있습니다.

`--fill-angle`이 `90deg`에서 `360deg`로 커질수록 뒤에 있던 투명한 영역이 줄어듭니다. 마지막에는 배경 전체가 색으로 채워지고 카드 주위에는 완성된 테두리가 남습니다.

## 브라우저에게 각도라고 알려준다

기본 CSS 변수는 값의 타입을 가지지 않습니다. 브라우저에게 `90deg`와 `360deg`는 계산 가능한 각도가 아니라 두 개의 문자열에 가깝습니다. 그대로 애니메이션하면 중간 각도를 만들지 못하고 값이 한 번에 바뀝니다.

`@property`는 CSS 변수의 타입과 초기 상태를 등록하는 문법입니다.

```css
@property --fill-angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 90deg;
}
```

`syntax`를 `<angle>`로 지정하면 브라우저는 이 값을 각도로 해석합니다. 이제 `90deg`와 `360deg` 사이의 값을 프레임마다 계산할 수 있습니다. `inherits: false`는 이 값이 카드 안의 자식 요소로 전달되지 않게 하고, `initial-value`는 애니메이션이 시작되기 전 보이는 호의 길이를 정합니다.

등록한 값을 keyframe에서 바꾸면 매 프레임 `conic-gradient`의 색상 경계가 다시 계산됩니다.

```css
@keyframes fill {
  from {
    --fill-angle: 90deg;
  }
  to {
    --fill-angle: 360deg;
  }
}
```

마지막으로 회전과 채우기를 같은 배경 레이어에 순서대로 실행합니다.

```css
animation:
  rotate 1.2s forwards,
  fill 0.8s forwards 1.2s;
```

첫 애니메이션은 배경의 `transform`을 회전시킵니다. 두 번째 애니메이션은 `1.2초` 뒤에 시작해 그라데이션의 각도를 채웁니다. 서로 다른 속성을 움직이기 때문에 하나의 `::before`에서 자연스럽게 이어집니다. 아래 타임라인을 움직여 두 단계가 연결되는 지점을 확인해 보세요.

## 내용은 읽는 순서대로 나타난다

테두리가 움직이는 동안 내용도 위에서부터 짧은 간격으로 나타납니다. 모든 영역을 동시에 보여주는 것보다 요약에서 세부 내용으로 시선이 자연스럽게 이동합니다.

```css
.section {
  opacity: 0;
  animation: reveal 0.6s forwards;
  animation-delay: calc(var(--index) * 0.3s);
}
```

이동과 블러는 초점이 맞는 정도로만 사용했습니다. 테두리와 내용을 동시에 진행해 효과 때문에 결과를 더 기다리게 만들지도 않았습니다.

## 움직임은 한 번이면 충분하다

이 효과는 로딩 상태가 아닙니다. 결과가 준비되었다는 변화를 전달한 뒤에는 멈춰야 내용을 읽을 수 있습니다. 그래서 처음 나타날 때와 다시 보기에서만 재생합니다.

모션 감소 설정에서는 회전과 순차 등장을 건너뛰고 완성된 테두리와 내용을 바로 보여줍니다. 효과가 없어도 결과의 의미와 사용 방법은 달라지지 않습니다.
