## 카드보다 어려웠던 태그

제목과 설명은 정해진 자리에 놓을 수 있습니다. 태그는 다릅니다. `CSS`, `TypeScript`, `Frontend Development`처럼 글자의 너비가 모두 다르고, 그에 따라 테두리와 다음 태그의 시작 위치도 달라져야 합니다.

모든 태그를 같은 너비로 만들면 짧은 단어에는 빈 공간이 남고 긴 단어는 잘립니다. 필요한 값은 태그의 글자 수가 아니라 실제로 화면에서 차지하는 너비입니다.

아래에서 태그를 바꿔보세요. 첫 번째 숫자는 글자의 실측 너비입니다. 여기에 좌우 여백 20px을 더한 값이 pill 전체 너비가 됩니다.

## 글자를 그리기 전에 잰다

HTML이라면 텍스트에 padding을 주고 `inline-flex`에 맡길 수 있습니다. 서버에서 SVG 문자열을 만들 때는 `<text>`가 차지할 공간을 레이아웃 엔진이 대신 계산해주지 않습니다. `<rect>`를 그리기 전에 글자 너비부터 구해야 합니다.

`@napi-rs/canvas`의 `measureText`는 문자열이 특정 글꼴과 크기에서 차지하는 너비를 돌려줍니다.

```ts
function getTextWidth(text: string, fontSize: number) {
  const context = canvas.createCanvas(1, 1).getContext("2d");
  context.font = `${fontSize}px ${fontFamily}`;

  return context.measureText(text).width;
}
```

여기서 Canvas는 이미지를 그리지 않습니다. SVG를 만들기 전에 필요한 숫자 하나만 계산합니다.

## 하나의 너비로 세 곳을 맞춘다

측정한 글자 너비에 20px을 더하면 태그의 전체 너비가 됩니다. 이 값은 세 곳에 함께 사용합니다.

1. `<rect>`의 너비
2. 가운데 정렬할 `<text>`의 x 좌표
3. 다음 태그가 시작할 x 좌표

```ts
const width = getTextWidth(tag, 12) + 20;

renderTag({
  width,
  textX: width / 2,
  x: previousX,
});

previousX += width + 6;
```

텍스트는 `x={width / 2}`와 `text-anchor="middle"`로 pill의 가운데에 놓습니다. 배경과 텍스트와 다음 위치가 같은 측정값에서 시작하므로 서로 따로 밀리지 않습니다.

## 카드의 경계에서 멈춘다

태그의 시작점에 새 너비를 더하면 오른쪽 끝을 알 수 있습니다. 카드 안쪽 영역인 400px을 넘는 태그는 그리지 않습니다.

```ts
if (previousX + width > 400) return;
```

이 검사는 태그를 자르는 대신 온전한 pill만 남깁니다. 짧은 태그가 여러 개 오든 긴 태그가 먼저 오든 같은 계산으로 배치할 수 있습니다.

## 측정값에는 여유가 필요하다

너비는 서버의 Canvas에서 측정하지만 SVG의 텍스트는 README를 보는 환경에서 렌더링됩니다. 같은 font stack과 글꼴 크기를 사용해 두 환경의 기준을 맞춥니다. 좌우 10px의 padding은 시각적 여백이면서 작은 렌더링 차이가 드러나지 않게 하는 여유이기도 합니다.

고정된 450px 카드 안에 길이가 매번 달라지는 콘텐츠를 넣으려면 먼저 그 콘텐츠를 숫자로 바꿔야 했습니다. 글자 너비를 구하자 태그의 배경, 중심, 다음 위치를 같은 규칙으로 설명할 수 있었습니다.
