## SVG 안에는 flex가 없다

카드에서 가장 재미있었던 문제는 태그였습니다. `CSS`, `TypeScript`, `Frontend Development`처럼 글자 수가 모두 다른데, 각 테두리는 텍스트에 꼭 맞아야 하고 다음 태그의 시작 위치도 달라져야 합니다.

HTML이라면 텍스트에 좌우 padding을 주고 `inline-flex`에 맡기면 끝납니다. 하지만 서버에서 하나의 SVG 문자열을 만들 때는 각 `<text>`가 차지할 너비를 레이아웃 엔진이 대신 계산해주지 않습니다. `<rect>`의 너비와 다음 태그의 `x` 좌표를 렌더링 전에 직접 정해야 합니다.

아래 입력값을 바꿔보세요. 글자의 실측 너비에 좌우 여백 20px을 더한 값이 태그 전체 너비가 됩니다.

## 글자를 먼저 잰다

서버에서는 `@napi-rs/canvas`의 `measureText`로 SVG에 들어갈 문자의 너비를 먼저 구합니다. 카드와 같은 글꼴 크기와 font stack을 사용해야 측정값과 실제 렌더링 사이의 차이를 줄일 수 있습니다.

```ts
function getTextWidth(text: string, fontSize: number) {
  const context = canvas.createCanvas(1, 1).getContext("2d");
  context.font = `${fontSize}px ${fontFamily}`;

  return context.measureText(text).width;
}
```

Canvas는 이미지를 그리기 위한 것이 아니라, SVG를 만들기 전에 필요한 숫자 하나를 얻기 위해 사용했습니다.

## 너비가 다음 위치를 만든다

측정한 글자 너비에 20px을 더해 pill의 너비를 만들고, 누적된 `x` 값에 배치합니다. 태그 하나를 그릴 때마다 자신의 너비와 6px 간격만큼 다음 시작점을 옮깁니다.

```ts
let x = 25;

for (const tag of tags) {
  const width = getTextWidth(tag, 12) + 20;
  if (x + width > 400) continue;

  renderTag({ x, width, textX: width / 2 });
  x += width + 6;
}
```

텍스트는 `x={width / 2}`와 `text-anchor="middle"`로 pill의 가운데에 놓습니다. 같은 측정값이 배경 너비, 텍스트 중심, 다음 태그 위치를 모두 결정하므로 세 요소가 따로 밀리지 않습니다.

## 측정과 렌더링 사이의 여유

너비는 서버의 Canvas에서 측정하지만 SVG의 텍스트는 README를 보는 환경에서 렌더링됩니다. 같은 font stack을 사용해 기준을 맞추고, 좌우 10px의 padding이 환경에 따른 작은 오차를 흡수합니다.

결국 450px로 고정된 카드 안에 길이가 매번 달라지는 콘텐츠를 넣는 일이었습니다. 태그를 그리기 전에 먼저 측정하자, 배경과 텍스트와 다음 위치가 하나의 값으로 연결됐습니다.
